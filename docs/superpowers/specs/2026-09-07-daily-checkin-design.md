# “日日有迹”个人任务与时间记录网站需求文档

- 文档版本：1.0
- 定稿日期：2026-09-07
- 产品类型：个人使用的响应式 Web 应用
- 部署目标：GitHub + Vercel + Supabase + 独立域名

## 1. 产品概述

“日日有迹”帮助单个用户每天列出待办事项，在执行过程中计时或事后补录耗时，完成后逐项打勾，并按周、月、季度回顾各类事情的时间投入。

产品首先是一张容易坚持使用的每日清单，其次才是统计工具。新增任务、开始计时、完成任务等高频操作必须在默认首页直接完成，不能被复杂的项目管理流程阻碍。

## 2. 产品目标

### 2.1 核心目标

1. 用户能在 10 秒内创建一项当天任务。
2. 用户能通过实时计时或手动补录准确记录任务耗时。
3. 用户完成一项任务时，可以直接打勾并看到当天进度变化。
4. 未完成任务不会丢失，而会自动出现在第二天。
5. 用户能清楚了解一周、一个月、一个季度的时间花在了哪些分类和标签上。
6. 数据可在手机和电脑之间同步，并能由用户自行导出备份。

### 2.2 成功标准

- 桌面端和手机端均可完成完整的“创建任务—计时—完成—查看统计”流程。
- 刷新页面或意外关闭浏览器后，正在运行的计时不会丢失。
- 周、月、季度统计结果与底层时间记录的汇总结果一致。
- 未完成任务在次日能自动显示，且原始计划日期和顺延天数准确。
- 除预设的个人账号外，其他访问者无法读取或修改任何任务数据。
- 用户可导出 CSV 和 JSON 文件，JSON 文件包含可恢复完整记录所需的数据。

## 3. 用户与使用范围

### 3.1 目标用户

仅供网站所有者本人使用，不提供公开注册、团队空间、分享或协作功能。

### 3.2 使用设备

- 电脑浏览器：用于安排任务、补录和周期复盘。
- 手机浏览器：用于随时查看清单、启动计时和完成任务。

### 3.3 第一版不包含

- 多人注册、团队协作、任务指派和公开分享。
- 番茄钟、专注白噪音和系统级应用拦截。
- 目标配额、积分、徽章、连续打卡排行榜等游戏化机制。
- 浏览器、邮件或手机系统通知。
- 第三方日历、Todo 或健康平台同步。
- AI 自动分类、总结或建议。
- 原生 iOS、Android 或桌面应用。

这些能力可作为后续迭代，不进入第一版验收范围。

## 4. 信息架构

登录后包含四个一级页面。

### 4.1 今日

默认首页，承担最高频的记录流程：

- 查看当天待办、进行中和已完成任务。
- 快速添加任务。
- 查看从之前日期顺延而来的任务。
- 查看重复规则在当天生成的任务。
- 启动、暂停计时器。
- 手动补录时间。
- 打勾完成、恢复为未完成或取消任务。
- 查看今日累计投入、完成数量、完成率和分类时间分布。

桌面端布局为左侧主导航、中间任务清单、右侧今日概览；手机端将主导航改为底部导航，并把今日概览放到任务清单下方。

### 4.2 日历

- 按月查看每天的任务数量、完成数量和累计耗时。
- 点击日期进入该日任务列表。
- 查看和编辑历史任务。
- 提前为未来日期安排一次性任务。

### 4.3 统计

- 切换周、月、季度范围。
- 查看总投入时间、完成任务数和任务完成率。
- 查看按分类汇总的时间与占比。
- 查看按标签汇总的时间排行。
- 查看每日或每周投入趋势。
- 查看与上一周期相比的总投入变化。
- 点击分类或标签，查看统计范围内对应的任务和时间明细。

### 4.4 设置

- 管理主分类。
- 管理自由标签。
- 管理重复任务规则。
- 设置个人账号与时区。
- 导出 CSV 或 JSON 数据。

## 5. 核心用户流程

### 5.1 每日记录

1. 用户登录后进入“今日”。
2. 页面展示当天重复任务、用户创建的任务，以及此前未完成的顺延任务。
3. 用户在快速输入框填写任务名称并保存。
4. 用户可立即为任务选择一个主分类和多个标签，也可稍后编辑。
5. 做事时启动该任务的计时器；如果另一任务正在计时，系统先暂停原任务。
6. 用户可以多次暂停和继续，每次形成独立时间段。
7. 忘记计时时，用户可手动补录开始/结束时间或直接填写耗时。
8. 完成后打勾，系统记录完成时间并更新今日概览。

### 5.2 未完成任务顺延

- 任务到次日仍未完成或取消时，自动出现在次日的“今日”列表。
- 任务只保留一条记录，不为每天的顺延创建重复副本。
- 系统保留原始计划日期，并计算已顺延天数。
- 用户可修改当前计划日期、完成任务或取消任务。
- 取消的任务不再顺延，但仍保留在历史记录中。

### 5.3 周期复盘

1. 用户进入“统计”。
2. 默认显示当前周，可切换到月或季度。
3. 用户查看总投入、完成情况、趋势和分类分布。
4. 用户点击某个分类或标签，查看组成该统计值的任务明细。
5. 用户可以导出当前筛选范围的 CSV，或从设置导出完整 JSON 备份。

## 6. 功能需求

### 6.1 账号与登录

- FR-AUTH-01：仅允许预设邮箱对应的个人账号登录。
- FR-AUTH-02：第一版采用邮箱和密码登录，不开放注册页面。
- FR-AUTH-03：未登录访问业务页面时必须跳转到登录页。
- FR-AUTH-04：登录状态可安全保持，用户也可主动退出。
- FR-AUTH-05：所有业务数据查询和写入必须限制为当前登录用户。

### 6.2 任务管理

- FR-TASK-01：任务名称为必填项，去除首尾空格后不得为空。
- FR-TASK-02：任务包含所属日期、一个可选主分类、多个标签、可选备注和可选预计时长。
- FR-TASK-03：状态包括待办、进行中、已完成、已取消。
- FR-TASK-04：完成任务时记录完成时间；恢复为未完成时清除完成时间，但保留已有时间记录。
- FR-TASK-05：取消任务时停止其正在运行的计时器。
- FR-TASK-06：支持编辑任务名称、日期、分类、标签、预计时长和备注。
- FR-TASK-07：删除任务采用软删除，并提供短暂的撤销入口；软删除记录不参与普通列表和统计。
- FR-TASK-08：任务列表优先显示进行中任务，其次为待办任务，最后为已完成任务。

### 6.3 计时与补录

- FR-TIME-01：同一账号同一时间只能有一个正在运行的计时器。
- FR-TIME-02：启动计时记录服务器时间；暂停时记录结束时间并计算该时间段耗时。
- FR-TIME-03：切换到另一任务时，先结束当前时间段，再启动新任务。
- FR-TIME-04：页面刷新、设备切换或浏览器关闭后，运行中的计时器根据服务器开始时间继续显示。
- FR-TIME-05：一个任务可拥有多个时间段，任务实际耗时为所有有效时间段之和。
- FR-TIME-06：用户可手动填写开始与结束时间，或直接填写耗时。
- FR-TIME-07：用户可编辑或删除错误的时间段，统计结果随之更新。
- FR-TIME-08：结束时间不得早于开始时间，直接填写的耗时必须大于零。
- FR-TIME-09：统计按用户当前时区的自然日汇总；跨午夜的时间段在统计时按午夜边界拆分，分别计入对应日期。

### 6.4 分类与标签

- FR-TAX-01：每个任务最多选择一个主分类。
- FR-TAX-02：每个任务可选择零个或多个标签。
- FR-TAX-03：支持创建、重命名、排序和归档分类与标签。
- FR-TAX-04：已被历史任务使用的分类和标签不得硬删除。
- FR-TAX-05：归档项不出现在新任务的默认选择列表中，但保留在历史任务和统计中。
- FR-TAX-06：分类名称和标签名称在同一账号内分别唯一。

### 6.5 重复任务

- FR-REC-01：支持每天、每周指定星期、每月指定日期三种重复模式。
- FR-REC-02：重复规则包含名称、分类、标签、预计时长、备注、开始日期和可选结束日期。
- FR-REC-03：重复规则可暂停、恢复或永久停用。
- FR-REC-04：系统为每个到期日期生成独立任务实例，同一规则同一日期不得重复生成。
- FR-REC-05：修改某一天的任务实例不影响其他实例。
- FR-REC-06：修改重复规则只影响尚未生成或尚未开始的未来任务。
- FR-REC-07：每月规则在某个月不存在对应日期时，于该月最后一天生成。例如每月 31 日在 2 月的最后一天生成。

### 6.6 自动顺延

- FR-ROLL-01：此前日期中仍为待办或进行中的任务自动显示在当天列表。
- FR-ROLL-02：顺延不修改原始计划日期，也不创建副本。
- FR-ROLL-03：顺延天数按当前日期与原始计划日期之间的自然日差计算。
- FR-ROLL-04：已完成、已取消或软删除任务不参与顺延。

### 6.7 统计

- FR-STAT-01：周统计默认以周一为一周开始，使用用户设置的时区。
- FR-STAT-02：月统计使用自然月；季度统计使用自然季度。
- FR-STAT-03：总投入时间等于统计区间内所有有效时间片段的时长之和。
- FR-STAT-04：任务完成数按完成时间落入统计区间计算，用于表示该周期实际完成了多少事项。
- FR-STAT-05：完成率按原始计划日期落入统计区间的任务计算，等于其中已完成任务数除以已完成、未完成和已取消任务总数；软删除任务不计入分母。任务在后续周期完成后，原计划周期的完成率允许随之更新。
- FR-STAT-06：分类统计按任务的主分类汇总；未分类任务归入“未分类”。
- FR-STAT-07：标签统计中，一段任务时间会计入该任务的每个标签，因此各标签耗时之和可能大于总投入时间，界面需明确说明。
- FR-STAT-08：上一周期对比采用等长的紧邻自然周期。
- FR-STAT-09：统计图支持查看具体数值，并提供对应任务明细。

### 6.8 数据导出

- FR-EXPORT-01：可按当前统计范围导出任务与耗时明细 CSV。
- FR-EXPORT-02：可导出完整 JSON 备份，包含任务、时间段、分类、标签、重复规则和设置。
- FR-EXPORT-03：导出文件名包含产品名、数据范围和生成日期。
- FR-EXPORT-04：导出动作只在登录状态下可用，不生成公开下载地址。

## 7. 数据模型

### 7.1 Profile

保存用户标识、展示名称、时区、周起始日和创建时间。虽然第一版只有一个用户，所有业务表仍通过 `user_id` 隔离，为权限规则提供明确边界。

### 7.2 Category

保存名称、排序、颜色标识、是否归档和时间戳。

### 7.3 Tag

保存名称、是否归档和时间戳。

### 7.4 Task

保存任务名称、原始计划日期、当前计划日期、状态、分类、预计时长、备注、来源重复规则、完成时间、取消时间、软删除时间和时间戳。

### 7.5 TaskTag

建立任务与标签的多对多关系，同一任务和标签组合保持唯一。

### 7.6 TimeEntry

保存所属任务、开始时间、结束时间、时长、记录来源（实时计时或手动补录）、是否正在运行和时间戳。数据库约束确保每个账号最多只有一条运行中的记录。

### 7.7 RecurrenceRule

保存任务模板、重复模式、星期集合或每月日期、开始/结束日期、启用状态和最后生成日期。

### 7.8 RecurrenceOccurrence

保存重复规则、发生日期与生成任务之间的关系，使用规则 ID 与发生日期的唯一约束防止重复生成。

## 8. 界面与视觉设计

### 8.1 品牌方向

- 产品名称：“日日有迹”。
- 主色为淡蓝色，搭配奶白背景和少量浅黄色强调。
- 使用圆润卡片、柔和描边、轻微阴影和适量留白。
- 卡通感通过友好的线性图标、小型状态插画和轻量完成动效表达。
- 整体保持清爽、克制和适合长期使用，避免幼儿化、强烈渐变和过多装饰。

### 8.2 交互原则

- 默认首页首屏直接显示快速新增输入框和任务清单。
- 打勾、计时、补录等高频操作无需进入详情页。
- 已完成任务弱化显示，但仍能快速恢复。
- 运行中的任务使用清晰但不过度刺激的淡蓝高亮。
- 完成任务时提供短促、不循环的卡通式反馈；遵循减少动态效果的系统偏好。
- 键盘、触控和鼠标均可完成核心流程；交互控件满足清晰焦点和足够触控尺寸。

### 8.3 空状态

- 今日无任务：提示“今天想留下什么足迹？”并突出新增入口。
- 统计无数据：说明完成或记录第一项任务后即可看到统计。
- 分类或标签无结果：保留筛选条件并提供返回全部的入口。

## 9. 系统架构

### 9.1 技术组成

- 应用框架：Next.js。
- 部署平台：Vercel。
- 源代码托管：GitHub。
- 数据库：Supabase 托管 PostgreSQL。
- 身份认证：Supabase Auth，邮箱密码方式。
- 域名：用户已有独立域名，正式环境绑定到 Vercel 项目。

### 9.2 数据流

1. 浏览器通过 Supabase Auth 获取个人会话。
2. 页面或服务端逻辑携带该会话访问 Supabase。
3. PostgreSQL 行级安全策略检查 `user_id`，只返回当前用户的数据。
4. 创建、计时、完成等操作成功后更新界面缓存。
5. 统计通过数据库查询或服务端聚合获得，不依赖浏览器本地缓存作为事实来源。

### 9.3 重复任务生成策略

第一版采用幂等的按需生成：用户打开“今日”、日历或相关接口时，系统检查并补齐应生成但尚未生成的任务。唯一约束确保多设备同时访问也不会生成重复实例。该策略不依赖额外的定时任务服务。

## 10. 安全与隐私

- Supabase 关闭公开注册，只建立所有者账号。
- 所有业务表启用行级安全策略，读写条件绑定当前认证用户。
- 服务端密钥只存放在 Vercel 环境变量中，不进入代码仓库或浏览器。
- 浏览器只使用允许公开使用的 Supabase 客户端配置。
- 登录错误不透露某个邮箱是否存在。
- 数据不设置公开分享链接，不接入第三方分析或广告脚本。
- CSV 与 JSON 导出由用户主动触发，并在生成后直接下载。

## 11. 异常与边界处理

- 网络中断：保留尚未提交的输入，提示重试，不显示虚假的成功状态。
- 重复提交：创建任务、生成重复实例和停止计时均使用幂等或唯一约束保护。
- 多设备计时冲突：数据库以账号级唯一运行记录为准；后启动的计时请求先停止旧记录。
- 浏览器关闭：计时依据服务器保存的开始时间恢复，而非依赖前端定时器计数。
- 无效补录：阻止负时长、零时长和结束早于开始的记录。
- 跨午夜计时：存储一条真实时间段，统计查询按用户时区在午夜边界拆分。
- 重复规则修改：不覆盖已开始、已完成或人工编辑过的历史实例。
- 统计空数据：显示零状态，不展示误导性百分比变化。

## 12. 非功能需求

- NFR-01：核心页面在常见手机与桌面宽度下均无横向溢出。
- NFR-02：页面支持键盘操作、可见焦点、语义标签及辅助技术读取。
- NFR-03：计时显示允许短暂客户端误差，持久化和统计结果必须以服务器时间为准。
- NFR-04：常用页面在正常网络下应快速反馈；写入操作期间显示明确状态并防止重复点击。
- NFR-05：日期时间统一以 UTC 存储，按用户时区展示和统计。
- NFR-06：敏感配置仅通过环境变量注入，仓库包含不含真实密钥的 `.env.example`。
- NFR-07：网站标题、描述和分享信息使用“日日有迹”的品牌文案。

## 13. 测试与验收

### 13.1 自动化测试重点

- 任务的创建、编辑、完成、恢复、取消和软删除。
- 多段计时累计、任务切换、手动补录和异常输入。
- 跨午夜时间拆分与时区转换。
- 每日、指定星期和每月重复规则的生成与去重。
- 未完成任务顺延及顺延天数计算。
- 周、月、季度边界和上一周期对比。
- 分类与标签归档后历史统计保持不变。
- 未登录访问和跨用户数据访问被拒绝。

### 13.2 关键验收场景

1. 创建“整理公众号选题”，选择“工作”分类和“公众号”标签，启动计时后刷新页面，计时继续。
2. 暂停并再次启动该任务，完成后总耗时等于两段时间之和。
3. 手动补录一次时间后，任务总耗时与周统计同步增加。
4. 当天未完成的任务在第二天显示为顺延任务，原始日期不变。
5. 每周一重复的任务只生成一次，修改本周实例不影响下周。
6. 在月末查看月统计，各分类汇总之和加上未分类时间等于总投入时间。
7. 退出登录后，业务页面和数据接口均不可访问。
8. 在手机端完成新增、计时和打勾流程，导航与操作区域无错位。
9. 导出的 CSV 可用常见表格软件打开，JSON 包含完整关联数据。

## 14. 发布与运维

### 14.1 所需资源

- 用户已有独立域名。
- 一个 GitHub 仓库，用于保存源代码。
- 一个 Vercel 项目，连接 GitHub 仓库并绑定域名。
- 一个 Supabase 项目，提供数据库和认证。

不需要自购 VPS、对象存储或独立邮件服务。

### 14.2 发布流程

1. 网站在本地完成开发和验证。
2. 源代码提交到用户指定的 GitHub 仓库。
3. Vercel 导入仓库并配置 Supabase 环境变量。
4. 执行数据库迁移并创建个人账号。
5. 验证预览环境后，将生产分支发布到 Vercel。
6. 在 Vercel 配置独立域名，并按域名服务商提示修改 DNS。

### 14.3 备份策略

- 第一版提供随时导出的完整 JSON 备份。
- 使用 Supabase 免费方案期间，建议用户定期下载 JSON 备份，并在重要数据积累后增加数据库级离线备份。
- 如升级到提供自动备份的付费方案，仍保留产品内导出功能，确保用户可迁移数据。
